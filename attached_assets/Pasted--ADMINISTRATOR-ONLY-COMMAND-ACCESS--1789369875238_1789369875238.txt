==================================================
ADMINISTRATOR-ONLY COMMAND ACCESS
==================================================

Simplify the bot's permission system.

Only Discord members who currently have the Discord Administrator permission may use the bot's administrative blacklist-management commands.

Do NOT use separate staff-role tiers for destructive commands.

Administrative commands should include:

/blacklist
/group_blacklist
/revoke_blacklist
/blacklist_note
/blacklist_sync
/identity_lookup
/security_status
/security_lockdown
/security_unlock
and any future blacklist-management/configuration commands.

Before EVERY administrative command executes:

Check the invoking member's CURRENT Discord permissions.

They must have:

Administrator = true

If they do not:

Deny the command.

Do not expose sensitive configuration or blacklist management information.

IMPORTANT:

Re-check Administrator permission AGAIN when the user presses any confirmation button.

Example:

Administrator starts /blacklist
↓
Confirmation appears
↓
Administrator permission is removed
↓
They press Confirm
↓
DENY THE ACTION

Never trust stale permissions from when the command originally started.


==================================================
SERVER OWNER SAFETY
==================================================

The Discord Server Owner should always be recognized as authorized.

However:

Administrator access does NOT bypass:

- blacklist rate limits
- global blacklist limits
- security lockdown
- confirmation requirements
- protected-user checks
- audit logging
- database safety checks
- duplicate checks
- Trello/database consistency checks

Being an Administrator means they are allowed to use the bot.

It does NOT mean they can bypass the bot's security systems.


==================================================
ANTI-ABUSE STILL APPLIES TO ADMINISTRATORS
==================================================

The bot must protect against a compromised Administrator account.

Example scenario:

Attacker gains access to an administrator account
↓
Starts mass-blacklisting members
↓
Bot detects abnormal volume
↓
Bot blocks additional blacklist actions
↓
Security Lockdown activates
↓
Audit channel receives HIGH PRIORITY warning

Therefore retain all anti-abuse systems even though commands are Administrator-only.

==================================================

Make the rate limit configurable through /setup.

Suggested default:

3

Time window:
5 minutes

Affected commands:

/group_blacklist
/revoke_blacklist

Allow these values to be changed through setup.

Example configuration:

3 actions

Window:
5 minutes

- Block the operation.
- Do NOT create/move Trello cards.
- Do NOT modify Discord roles.
- Log a security alert.

Example:

@ExampleAdmin

Window:

==================================================
MIGRATION
==================================================

If the current bot has old authorized-role/staff-role settings:

Do not break the database.

Migrate away from those permission checks cleanly.

The bot should now use:

member.permissions.has(Administrator)

or the correct equivalent for the Discord.js version being used.

Old role permission configuration may be removed from the active permission logic.

Do not delete unrelated configuration.
